Chapter 2 applied

The eight-part business model

A store is more than its pages. These decisions explain how NovaTech would create value, reach customers, organize the work, and earn revenue if developed beyond the academic demo.

01Value proposition
A focused, easy-to-compare catalog of practical accessories with transparent descriptions and a low-friction shopping journey.
02Revenue model
Direct product sales would be the primary model. Advertising, subscriptions, referral fees, and real transactions are not part of this release.
03Market opportunity
The initial niche is students and professionals in Canada who need dependable audio, charging, wearable, and productivity accessories.
04Competitive environment
Large marketplaces, electronics chains, brand stores, and specialist accessory sellers compete for the same customer attention.
05Competitive advantage
NovaTech differentiates through a carefully limited assortment, clearer comparison information, accessible design, and visible privacy choices.
06Market strategy
Helpful team articles, buying guides, shareable content, search-friendly product language, and a public portfolio presence would attract the niche.
07Organizational development
The four-person group divides product research, experience design, catalog operations, privacy review, content, testing, and release work.
08Management team
Elias Zubaidi (payments), Awale Hussein (SEO), Hasan Muhammad (cart and QA), and Omeed Attayi (content and social) collectively own the project vision and execution.

Operations & competition

From supply to customer value

The current demo focuses on the retail-facing steps. A commercial version would connect additional partners and operational systems into a complete value web.

  1. 1SourceEvaluate manufacturers, quality, compatibility, and responsible supplier terms.
  2. 2MerchandiseSelect a focused assortment and maintain accurate product information.
  3. 3DiscoverUse search, filters, content, and clear pricing to lower decision effort.
  4. 4TransactSecure PayPal sandbox checkout, 13% HST, and order confirmation are live; real inventory comes in a future release.
  5. 5Deliver & supportCoordinate carriers, returns, service, and feedback after purchase.

Primary competitive choice

Focused differentiation

NovaTech competes on clarity, curation, accessibility, and trust rather than attempting to be the lowest-price mass marketplace. Its first scope is a narrow accessory niche, with customer intimacy supported by useful content and honest controls.

Future value web

Partners that make the model work

Suppliers, a payment processor, GitHub or another cloud host, shipping carriers, and customer-support tools would coordinate through Internet-based systems. PayPal already handles payments in sandbox mode; the other partners add capabilities this classroom release does not simulate yet.

Chapter 3 applied

How the public website works

The Internet supplies the network; the Web supplies the linked pages and browser standards. NovaTech uses both while keeping its application layer intentionally small and transparent.

📱

Client

Browser on phone or computer

Requests pages, renders the interface, runs JavaScript, and keeps the demo cart in local storage.

→
🌐

Internet & Web

DNS, HTTPS, TCP/IP, and routing

DNS connects the human-readable host to network infrastructure; HTTPS carries protected web requests over the Internet.

→
☁️

Server

GitHub Pages cloud hosting

Stores and delivers the static HTML, CSS, and JavaScript files from a scalable hosted service.

Domain names, DNS & URLs

The published URL identifies NovaTech’s location on the Web. DNS and GitHub’s hosting infrastructure resolve and serve that address.

Client/server model

The browser is the client; GitHub Pages is the server. There is no NovaTech application server or customer database in this version.

Mobile platform

Responsive grids, touch-sized controls, flexible typography, and mobile navigation support shopping from smaller screens.

Cloud computing

Managed hosting reduces deployment and infrastructure work, but it also means availability and delivery depend on the provider.

Protocols & packet delivery

Browsers and hosts rely on standardized networking layers, including IP addressing, packet routing, TCP or QUIC, and HTTP. These are infrastructure services—not JavaScript features we re-create.

HTTPS & security

HTTPS protects data in transit. NovaTech further limits risk by collecting no account, address, payment, analytics, or newsletter data.
